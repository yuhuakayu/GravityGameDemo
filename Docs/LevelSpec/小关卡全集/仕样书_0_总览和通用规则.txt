仕样书 0：小关卡全集 总览和通用规则（先读这份）

目标：游戏里做出 20 个小关卡，玩法、数值和原型一样。
本套文件都在 Docs/LevelSpec/小关卡全集/ ：
  仕样书_0_总览和通用规则.txt   本文件：关卡顺序、坐标换算、擦边慢动作、镜头、生成器
  仕样书_1_迷宫.txt             Maze_01～08（老 01～03 保留，新做 04～08）
  仕样书_2_矿坑.txt             Mine_01～04
  仕样书_3_岩浆.txt             Lava_01～04
  仕样书_4_天空.txt             Sky_01～04
  原型/   迷宫、矿坑、岩浆、天空各一个"世界名_原型.html"，浏览器直接打开能看演示、自己玩；"世界名_原型代码.js"是机关的参照实现（各仕样书写了对应的函数名）
  数据/   矿坑、岩浆、天空每关的数据（JSON）
  素材/   每关的整关图和机关贴图（16 像素 = 1 格）
单位：本套文件里的"格"= 1 个 Unity 单位 = 16 像素（迷宫地图的一个字符是 2×2 格，迷宫仕样书里叫"地图格"）。
作废：Docs/LevelSpec/仕样书_动作迷宫五关.txt 和 Docs/LevelSpec/动作迷宫/ 整个文件夹，被本套取代，不要再用。

建议顺序：先做本文件的通用部分 → 迷宫 → 矿坑 → 岩浆 → 天空。每做完一个世界汇报一次。

====================================
二、和原型的关系
====================================

1. 玩家、门（GoalDoor 重力锁）、尖刺、激光、世界旋转：用游戏里现有的实现，不照原型重写（原型本来就是照游戏写的）。
2. 机关（落石、塌方、矿车、木板、岩浆、跷跷板、气球雷、散云、气球平台、云海）：照原型代码在"关卡坐标"里自己模拟，不用 Rigidbody2D 动力学。
   每个 FixedUpdate 走一步，dt = Time.fixedDeltaTime = 0.02（原型也是 0.02 一步）。机关组件的执行顺序排在 WorldRotator（-250）之后、PlayerController 之前。
   显示在 Update 里按上一步和这一步的位置插值（原型 render 里的 alpha），慢动作时才不会一卡一卡。
3. 原型里只给演示用的东西不做：每关的"第 N 拍"提示、方向盘、时间轴、自动演示、开场标题卡、通关/死亡大字。
4. 这里写的数值和原型代码不一样时以这里为准；这里没写到的细节看原型代码。

====================================
三、关卡坐标（矿坑、岩浆、天空通用）
====================================

1. 数据里的坐标和原型一样：1 格 = 1 个 Unity 单位，原点在关卡左上角，x 向右，y 向下。w、h 是关卡的格数。
2. 在世界根节点（WorldRotator 那个物体）下建一个 "Level"，localPosition = (-w/2, h/2, 0)，不旋转。
   关卡点 (x, y) 就是 Level 的本地坐标 (x, -y)。整关图、碰撞 Tilemap、所有机关都放在 Level 下面，跟着世界一起转。
3. Tilemap 的 Grid 放在 Level 原点；关卡格 (cx, cy) 对应 cell (cx, -cy - 1)。
4. 角度：关卡坐标里顺时针为正（因为 y 向下），设到 Unity 的 localRotation z 时取负号。
5. 世界转角 θ = WorldRotator.ClockwiseAngleReadout（度，顺时针为正）。关卡坐标里的重力方向 g = (sin θ, cos θ)，"屏幕上方" = -g。G = 9.81。
6. 判定玩家：取玩家 CapsuleCollider2D 两端圆的圆心和半径，用 Level.InverseTransformPoint 换到关卡坐标（再把 y 取负）。
   原型按"圆心在脚底往上 0.4 和 1.13、半径 0.4"写的，各仕样书里的 PR = 0.4 就是这个半径。
   需要玩家速度时，把 PlayerController.IntendedVelocity 同样换到关卡坐标。
7. 死亡一律调用 PlayerController.Die()（现有流程：红光 → 重开本关 → 回到预览）。机关状态随场景重载复位。
8. 门：每关数据里的 door = { bx, by, dir }。用模板里的 GoalDoor，门图底边中点对齐关卡点 (bx, by)，localRotation z = dir
   （dir 0 门在地上，90 门在右墙上，-90 门在左墙上；对齐算法和迷宫 PlaceDoor 一样）。GravityLockDoorSetup.Apply(door)。

====================================
四、旋转速度和下落速度上限
====================================

1. PlayerController 加 public float maxFallSpeed = 0（0 表示不限，老场景不受影响）。
   BuildIntendedVelocity 加完重力之后：if (maxFallSpeed > 0 && intendedVelocity.y < -maxFallSpeed) intendedVelocity.y = -maxFallSpeed;
2. 生成器写进场景：Maze_01～03 保持 0；Maze_04～08、矿坑、岩浆 = 16；天空 = 11（原型的 VMAX / vmax）。
3. 世界旋转（WorldRotator）：迷宫 8 关保持模板原值。
   矿坑、岩浆、天空 12 关的原型是按 180°/s 调的：rotateSpeed = 180，maxAngularSpeed = 180，maxStepAngle = 3.6（0.02 秒一步 × 180°/s）。

====================================
五、擦边慢动作（20 关通用）
====================================

1. 新组件 NearMissFeedback，每个关卡场景一个（生成器添加）。方法 NearMiss(string kind)：
   同一种 kind 在冷却时间内只触发一次（冷却：迷宫、天空 1.4 秒；矿坑、岩浆 1.6 秒，生成器按世界设）；
   触发时：玩家旁边弹出大字"险！"，同时慢动作。
2. 慢动作：Time.timeScale = 0.32，持续 0.42 秒真实时间（unscaledDeltaTime 计时），到时恢复 1。
   不改 fixedDeltaTime（物理还是 0.02 一步，只是每秒的步数变少，和原型一样）。
   暂停优先：timeScale 为 0 时不触发；恢复时只有 timeScale 还是 0.32 才改回 1。
   玩家死亡、通关进门时立刻恢复 1；组件 OnDisable / OnDestroy 时如果还是 0.32 也恢复 1（timeScale 跨场景不会自己复原，重开关卡不能卡在慢动作）。
   慢动作期间再触发（别的 kind），重新计满 0.42 秒。
   计时规则：只有慢动作这 0.42 秒按真实时间；冷却、弹字的寿命、震屏衰减都按游戏时间（Time.deltaTime / Time.time），慢动作时跟着变慢，和原型一样。
3. 弹字（"险！"大字和各世界的小字）：字体 NotoSerifSC-Bold-GB2312 Pixel，描边粗细大小字一样，约屏幕高度的 0.6%。屏幕方向摆放，不跟世界转。
   每帧跟着玩家当前的脚底位置走，再往屏幕上方飘，速度 1.6 格/秒。同时最多 3 个字，来第 4 个时删掉最老的。
   大字：字高约屏幕高度的 5%，起点在脚底往屏幕右 1.6 格、往屏幕上 2.4 格，寿命 0.9 秒，不透明度 = clamp((1 - t / 0.9) × 1.5, 0, 1)。
   小字：字高约屏幕高度的 3%，起点在脚底正上方 2.4 格，寿命 0.8 秒，不透明度 = clamp((1 - t / 0.8) × 1.5, 0, 1)。
4. 弹字颜色按世界（大字 / 小字 / 描边）：
   迷宫 #FF8AA6 / #E6E2FF / 黑色，不透明度 0.75
   矿坑 #FF8A6A / #FFE2BD / 黑色，0.75
   岩浆 #FFD27A / #FFE2BD / 黑色，0.75
   天空 #FFD166 / #FFFFFF / (20,40,70)，0.75
5. 文字走 LocalizationManager，新增这些 key（中 / 日 / 英）：
   hud.near_miss    险！ / 危ない！ / CLOSE!
   pop.rumble       轰隆隆… / ゴゴゴ… / RUMBLE...
   pop.creak        嘎吱… / ギシッ… / CREAK...
   pop.snap         咔嚓 / バキッ / SNAP!
   pop.crash        哐！ / ガシャン！ / CRASH!
   pop.lava_wake    岩浆活了！ / 溶岩が動いた！ / THE LAVA WAKES!
   pop.tip          咔！ / カチッ！ / CLACK!
   pop.cloud_fade   云要散了！ / 雲が消える！ / FADING!
   pop.balloon_up   被气球带上去了 / 風船で上昇！ / UP WE GO!
   pop.balloon_pop  啪！ / パン！ / POP!
6. 每个世界什么时候算"擦边"写在各自的仕样书里。

====================================
六、镜头（矿坑、岩浆、天空；迷宫照旧用 MazeCameraFit）
====================================

新组件 SmallLevelCamera，挂主摄像机。这些场景里 FollowTarget2D 关掉，不加 MazeCameraFit。摄像机本身不旋转（转的是世界）。
1. 正交大小固定：M = max(w, h)，size = max((M + 3) / 2, (M + 8) / (2 × aspect))。
   天空：M = max(云海边界宽, 云海边界高)，size = max((M + 2) / 2, (M + 7) / (2 × aspect))。
2. 跟随点 = C + 0.4 × (P - C)。C = 关卡中心的世界坐标（天空用云海边界的中心），P = 玩家脚底的世界坐标再往屏幕上 0.8。
3. 每帧：pos += (跟随点 - pos) × (1 - exp(-k × Time.deltaTime))，k = 7（天空 6）。用 deltaTime，慢动作时镜头也跟着慢。开场直接放到跟随点。
4. 原型里跟随点画在屏幕高度 53% 的地方（略低于正中）：摄像机 y = pos.y + 0.06 × size。
5. 震屏 Shake(a)：当前值取 max(当前, a)，每秒衰减成 exp(-6)。每帧摄像机额外偏移 x、y 各 (随机 -0.5～0.5) × a × 0.9。各机关的震屏值写在各仕样书里。
6. LevelIntroUI 预览时照它现在处理 MazeCameraFit 的方式处理 SmallLevelCamera：预览时让出摄像机，按开始以后恢复，并直接放到跟随点。

====================================
七、画面小效果（照原型）
====================================

1. 速度线（20 关）：玩家竖直方向（屏幕方向）的速度绝对值超过 7.5（天空 7）时，在玩家上方画几条竖直细线（宽 0.035 格），每秒随机重排 14 次。
   迷宫只在活着时画；矿坑、岩浆往屏幕上方飞时（例如矿车撞车被甩上去）整组线上下翻过来（起点往下偏，线朝下画）。
   迷宫：条数 min(12, floor((速度 - 7) × 2))；每条横向在玩家 ±2.5 格内随机，起点在脚底往上 0.8 再往上 -1～4 格随机，往上长 1.0 + 速度 × 0.1 格；颜色 (214,220,255, 不透明度 0.28)。
   矿坑、岩浆：条数 min(14, floor((速度 - 7) × 2.2))，横向 ±3.5 格，起点再往上 -1.2～4.8 格，长 1.2 + 速度 × 0.12 格；颜色 (255,236,210, 0.28)。
   天空：条数 min(14, floor((速度 - 6.5) × 2.4))，其余同矿坑；颜色 (255,255,255, 0.55)。
   矿坑坐在矿车里时线的方向改成和矿车在屏幕上的运动方向相反（见矿坑）。
2. 暗角（屏幕空间）：径向渐变，中心在屏幕高度 53% 处，0.3 倍屏高以内透明，到 0.95 倍屏高处达到最深。
   矿坑：黑色，最深 0.55；岩浆：(18,3,0)，最深 0.55；迷宫：黑色，0.35 倍屏高以内透明，到 0.95 倍处最深 0.45。
   天空：平时没有；玩家活着、下面那个圆心离云海边界不到 3 格时出现红色 (230,60,80) 暗角，0.3 倍屏高以内透明，到 0.9 倍处最深 = (3 - 距离) / 3 × 0.45。
3. 碎屑、火星、尘土这类粒子用简单 ParticleSystem 就行，颜色写在各仕样书里，不用追求和原型一模一样。

====================================
八、新生成器（矿坑、岩浆、天空 12 关）
====================================

新建 Editor/SmallLevelSceneBuilder.cs，菜单 Tools/Gravity Game/Levels/Build Small Levels。
读 Assets/Resource/LevelData/ 下的 mine_levels.json、lava_levels.json、sky_levels.json，生成 Mine_01～04、Lava_01～04、Sky_01～04。
流程照 MazeSceneBuilder：复制 Stage2 模板，保留并设置玩家、门、摄像机、LevelIntroUI，清空世界根节点，然后：
1. 建 Level 和 Grid（第三节）。Tilemap "Walls"：Wall 层，碰撞和迷宫一样（Kinematic Rigidbody2D + TilemapCollider2D + CompositeCollider2D，加进 world.attachedGeometryBodies）。
   TilemapRenderer 关掉，只要碰撞；看到的是整关图。实心格：
   矿坑、岩浆：整张图先全是实心，carve 里的矩形挖空，fill 里的矩形再填回（矩形是 [x0, y0, x1, y1]，含 x0、不含 x1）；
   天空：isles 里的矩形是实心，其余都是空的（关卡外也是空的）。
2. 整关图 level_场景名.png 放在 Level 原点（pivot 左上）。
3. 门按第三节第 8 条，nextSceneName 按第一节。
4. 玩家脚底放在数据里的 start（矿坑、岩浆是 start.feet；天空是 start），和 PlacePlayer 一样再往上抬 0.02。Mine_03 开局坐在矿车里（见矿坑仕样书）。
5. 摄像机：SmallLevelCamera；背景色 矿坑 (43,32,25)、岩浆 (38,18,15)、天空 (238,242,249)。
   LevelIntroUI.boundsCenter / boundsSize 设成关卡范围（天空用云海边界），换算成世界坐标。
6. WorldRotator 的三个速度值、PlayerController.maxFallSpeed 按第四节。
7. 加 NearMissFeedback（第五节）和这个世界的机关组件，数据由生成器从 JSON 读出后序列化进组件（运行时不读 JSON）。
8. 注册 Build Settings、重写选关列表（第一节）。

素材导入：
  素材/矿坑 → Assets/Resource/Art/SmallLevels/Mine/，素材/岩浆 → .../Lava/，素材/天空 → .../Sky/（Sprites 子文件夹一起）。
  数据/ 下的三个 json → Assets/Resource/LevelData/。
  导入设置：Sprite、Pixels Per Unit 16、Filter Point、不压缩、不要 mipmap。
  整关图 pivot 左上 (0, 1)；Sprites 里每张图的 pivot 写在对应 JSON 的 "sprites" 里（px 是像素尺寸，pivot 是归一化坐标，左下为 0）。
