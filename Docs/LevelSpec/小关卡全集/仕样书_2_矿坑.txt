仕样书 2：矿坑 Mine_01～04（落石、塌方、矿车、木板）

先读 仕样书_0_总览和通用规则.txt（坐标换算、擦边慢动作、镜头、生成器都在那里）。
原型页：原型/矿坑_原型.html；参照实现：原型/矿坑_原型代码.js（下面括号里是对应的函数名）。
数据：数据/mine_levels.json；图：素材/矿坑/level_Mine_0N.png；贴图：素材/矿坑/Sprites/。
本世界：PR = 0.4，G = 9.81，玩家下落上限 16，旋转 180°/s，擦边冷却 1.6 秒，摄像机背景 (43,32,25)，黑色暗角。

====================================
一、通用
====================================

1. 实心格 = 没挖空的岩石格 + 塌方填上的碎石格；关卡外也算实心。落石用这张格子表判碰撞，不用 Physics2D。
2. 圆和格子的碰撞（resolveCircleL）：最多迭代 4 次，每次把圆心附近每个实心格的最近点算出来，重叠就沿"最近点 → 圆心"方向推出去；
   圆心已经在实心格里面时，往这一格四个面里最近的、并且那一边不是实心的方向推出去。推出的方向就是碰撞法线。
3. 机关组件只在正式开始以后（预览结束、玩家第一次 IsGameplayActive 之后）才模拟。玩家死后红光那 0.5 秒里落石和木板继续动，塌方和矿车停住。
4. 显示顺序（低到高）：整关图 → 碎石 → 门 → 木板、落石 → 粒子 → 矿车车架 → 钢索 → 玩家 → 吊斗前片。
5. 粒子颜色：火花 #FFD37A，木屑 #A8743C，碎石屑 #8A8A92，尘土 #8A7462（半透明）。

====================================
二、Mine_01 落石（stepRocks）
====================================

数据 rocks：[x, y, 半径 r, 松动方向]，rockDelay = 1.5。贴图 rock_r45（r 0.45）、rock_r42（r 0.42）。
1. 三个状态：卡着 → 晃动 → 掉落。
   卡着：重力方向 g 往松动方向偏过 25° 就开始晃：right 是 g.x > sin25°，left 是 g.x < -sin25°。
   晃动：rockDelay 秒（显示每帧随机抖 ±0.04 格），然后掉落。
2. 掉落：每步 v += g × G × dt，速度上限 15；分 2 个子步：位置 += v × dt / 2，再和格子做碰撞；
   对每个碰撞法线 n：vn = v·n，vn < 0 时：vn < -3.5 就碎掉（石头消失，碎石屑 14 个，震屏 0.35，尘土）；
   否则 v -= 1.2 × vn × n，再 v ×= 0.995（几乎不弹，贴着地滚）。
   显示旋转：rot += (vx × g.y - vy × g.x) × dt / r（关卡坐标里的角度，设到 Unity 时取负）。
3. 石头之间：两块里至少一块在掉落就互相推开（各推一半重叠量，只推掉落的那块）。n = a 指向 b 的单位向量，rv = (b.v - a.v)·n，rv < 0 时冲量 im = -rv × 0.6，a.v -= n × im，b.v += n × im（两块都改）。
4. 圆心落在碎石格里的石头直接删掉（本关没有塌方，照写即可）。
5. 判定（只看掉落中的石头）：rel = |石头速度 - 玩家速度|（都在关卡坐标里），d = 玩家圆心到石头中心的距离。
   死亡：d < r + PR - 0.1 并且 rel > 2.5。擦边 "rock"：d < r + PR + 2.0 并且 rel > 3。

====================================
三、塌方（Mine_02、Mine_03；stepCave、fillCave）
====================================

数据 cave：route（[x0, y0, x1, y1, 方向] 的列表，方向 R/L/D），delay，以及 lag 或 speed/hurry/lagEnd/nearRide。
1. 路线距离：按 route 顺序，每个矩形里每一格的距离 = base + （R：x + 0.5 - x0；L：x1 - (x + 0.5)；D：y + 0.5 - y0），
   走完一个矩形 base += （D：y1 - y0；R、L：x1 - x0）。所有格按距离从小到大排好（两关的矩形互不重叠）。
2. 开始：世界第一次转过 20°（cos θ < cos20°）记下时刻，震屏 0.3，小字 pop.rumble。之后 delay 秒内只震屏 0.06，然后塌方前沿 front 从 0 开始走，记录表 H 初始为 [(此刻, 0)]。
3. 玩家的路线距离 dp = 两个圆心所在格的路线距离取大（不在路线上算 -1）。记录表 H 每步追加 (时刻, max(上一条的值, dp))。gap = dp < 0 ? 0 : dp - front。
4. 前沿怎么走，两种模式：
   延迟模式（Mine_02 用 lag = 1.35；Mine_03 撞车以后用 lagEnd = 1.3）：塌方照着你走过的路线、晚 lag 秒跟过来。
     tq = 现在 - lag；H 里第二条的时刻 ≤ tq 时就丢掉第一条；target = H 第一条的时刻 ≤ tq ? 它的值 : 0；
     front = min(front + 16 × dt, max(front, target))。
   速度模式（Mine_03 撞车前）：H 只留最近 3 秒（至少留 2 条）；front += speed（8.3）× hurry × dt，gap > 6 时 hurry = 1.4，否则 1。
5. 填格：所有路线距离 ≤ front 的格变成碎石（实心）。塌方进行中一直震屏 0.1。
   碎石要挡玩家：建第二个 Tilemap "Rubble"（Wall 层，TilemapCollider2D，不用 Composite，放在 Level 下跟着世界刚体走），塌一格 SetTile 一格。
   显示用 rubble_0～7（第 (cx × 7 + cy × 13) mod 8 张），一半的格子冒点尘土。
6. 判定：玩家每个圆心附近（骑车时 3.2 格，否则 1.4 格）的碎石格，d = 圆心到这一格方块的距离。
   死亡：d < PR - 0.15。擦边 "cave"：d < PR + 0.9（Mine_03 骑车时用 nearRide = 2.6）。

====================================
四、Mine_03 矿车（stepCart、crash、stepPlayer 的 riding 部分）
====================================

数据 track（折线，关卡坐标），cornerKeep = 0.7，开局坐在车里。贴图 cart_trolley、cart_bucket_front。
1. 车的状态：s（沿轨道的距离，0～总长）、v。每步：
   t = 当前段的单位方向，a = G × (g·t)（g 是重力方向）；
   |v| < 0.05 并且 |a| < 0.1 × G 时 v = 0、不动；
   否则 v = clamp(v + (a - 0.12 × v) × dt, -11, 11)，s += v × dt；
   所在的段号变了（往回滚过弯也算）v ×= cornerKeep，震屏 0.25，冒 8 个火花；s < 0 时 s = 0、v = max(0, v)；s ≥ 总长时 s = 总长，撞车。
   |v| > 7 时每步 60% 机率从车轮处冒火花。
2. 坐车：轨道点 = 轨道上 s 处的点（世界坐标）。每个物理步玩家 Rigidbody2D 设成 Kinematic，用 MovePosition 把脚底放到"轨道点往屏幕下 1.05"，速度清零。
   坐车时动画按站着处理（PlayerController 需要一个强制着地的开关）。
   世界的旋转中心 = 轨道点：Level 下放一个跟着轨道点走的空物体，坐车时设成 WorldRotator.pivot，撞车后设回 null。
3. 撞车（crash）：玩家放开（恢复 Dynamic），速度 = (0, 车在世界坐标里速度的 y 分量，限制在 ±16)；震屏 0.7，碎片 26 个，小字 pop.crash。
   之后塌方换成延迟模式（lagEnd = 1.3）。
4. 显示：
   车架 cart_trolley 放在轨道点，沿当前段方向旋转；撞车后在这个角度上再顺时针歪 0.35 弧度，停在轨道尽头。
   吊斗前片 cart_bucket_front 放在"轨道点往屏幕下 0.55"，不跟世界转（永远竖直），盖住玩家的腿；撞车后吊斗照样挂在那里。
   钢索：从轨道点到吊斗点往屏幕上 0.3，宽 0.06，颜色 #6F6F78，在玩家下面。
   断轨和警示条已经画在整关图里。
   坐车时速度线方向：和车在屏幕上的运动方向相反，|v| > 7.5 才出。
5. 塌方判定按第三节，骑车时搜索 3.2 格，擦边用 d < PR + 2.6。

====================================
五、Mine_04 木板（stepPlanks）
====================================

数据 planks：x0、x1（竖井左右），top（木板开始的 y），bottom（落到底的 y），wire（绊线 y），delay，h = 0.36。贴图 plank_held、plank_free（中心对齐）。
木板只沿关卡的 y 方向动，不和玩家碰撞，只判定砸到。lp = 玩家下面那个圆心（关卡坐标）。
1. 卡着：玩家活着、lp 在竖井里（x0 < lp.x < x1 并且 lp.y > top），并且重力基本朝下（cos θ > cos45°）→ 开始嘎吱：倒计时 2.5 秒，震屏 0.12，小字 pop.creak。
2. 嘎吱：显示每帧随机抖 ±0.04 格。玩家还在竖井里并且 lp.y > wire（第一次）→ 倒计时 = min(倒计时, delay)（delay 是 0，就是马上断）。
   倒计时到 0 → 掉落，小字 pop.snap。
3. 掉落：v += (G × cos θ - 0.1 × v) × dt，y += v × dt；y < top 时 y = top、v = 0；y ≥ bottom 时 y = bottom，停住，震屏 0.55，木屑 22 个。
4. 判定（掉落中并且 v > 2）：圆心 x 在 (x0 - PR, x1 + PR) 之间，dy = |圆心 y - 木板 y|。
   死亡：dy < h/2 + PR - 0.08。擦边 "plank"：dy < h/2 + PR + 1.0。
5. 显示：卡着、嘎吱用 plank_held（两头带卡扣），掉落以后用 plank_free；中心 x = (x0 + x1) / 2。
