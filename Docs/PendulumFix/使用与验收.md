# Stage1 摆板连接、旋转碰撞与自动移动暂停

本轮在原有 `PlayerController`、`WorldRotator`、`PivotPendulum` 和 `CrushGuard` 上扩展。没有修改 Physics 2D 全局求解参数、玩家 Trigger 状态或使用摩擦材质替代碰撞修复。

## 场景改动

| 物体 | 改动 |
| --- | --- |
| Clock | `hingePoint` 指向自身 Circle；长轴为本地 X；范围 0～90°；初始铰链对齐；实体碰撞层改为 Box |
| Clock (1) | `hingePoint` 指向自身 Circle；长轴为本地 X；范围 -90～0°；初始铰链对齐；实体碰撞层改为 Box |
| WorldRoot/StrandForClock、StrandForClock (1) | 本地 Z 旋转均为 90°；X 缩放均为 6.994802；Y 坐标均为 2.3302；X 为 0.217138 和 15.859999，沿原机关中线 8.038568 对称；碰撞层改为 Box |
| 两个 StrandForClock 下的 Cricl | 保留作为外部转轴；实体碰撞层改为 Box |
| Player | 开启 `pauseAutoMoveWhileRotating`，恢复等待 0.15 秒，绑定本场景 WorldRoot |

两板的 `gravity=120`、`angularDamping=3`、`bounciness=0.08` 保持不变。Stage1 已保存引用，无需再手动拖拽。

## 实现

- `PivotPendulum` 先将 Circle 与外部 pivot 对齐，再缓存实际铰链偏移和板长轴。Grivity 仅决定臂长，不再定义角度或板的位置。
- 执行顺序为 GyroRuntime -300、WorldRotator -250、PivotPendulum -200、PlayerController -100。根节点发布下一物理步的位置、角度和 up；摆板用同一姿态计算铰链，避免读取插值 Transform 导致一帧延迟。
- `KinematicMotionSafety` 限制最远几何点的每步位移，小于玩家最小厚度的一半；独立摆动先扣除根节点带来的运动。根运动为摆板预留 30% 的点位移预算。
- 根旋转还使用原生碰撞形状预测下一姿态是否能在现有修复预算内脱离，预测保留 0.002 单位间隙。若两侧形成夹缝，先减慢或暂缓该步旋转，再由 `PushAlongGravity` 沿可行的反重力切向逐步抬出。抬出经过形状投射与终点碰撞检查，和普通修复共用每步 0.15 单位预算，不修改玩家速度。
- `CrushGuard` 在模拟前记录进入接触的原侧，使用真实刚体姿态转换接触面，并按胶囊原生形状计算支撑距离。修复时同时满足多条接触面约束，保留当前步已处理的 Composite 面，避免多个修正互相抵消。仍使用 0.15 单位全步修复预算和 3 次重叠迭代，且不向刚体注入速度。
- Stage1 的摆板、支架和转轴碰撞体原来处于 Background 层，而玩家的地面、墙壁与 CrushGuard 掩码只含 Wall、Box。它们现在统一使用 Box，进入原有的接触投影和防穿透流程。
- 自动移动只暂停横向输入贡献；重力、喷气背包与防推动流程继续执行。只有 `IsRotating` 连续为 false 达到恢复等待时间后才恢复自动移动；关闭 Inspector 开关后恢复原行为。
- 速度模式的过期旋转输入有时间上限，避免安全限速后松手仍长时间追赶积压；绝对角度目标仍保留。

## 测试说明

修改前先保存并复现：场景两侧铰链初始偏移分别约 0.897454 / 1.256137 单位；旧脚本展开到限制角后的长轴夹角误差约 24.13049°；120°/秒的旧物理步进测得最大铰链间距约 1.191264 单位。原侧修复专项也复现了薄墙越过玩家中心后，最短距离修正把玩家推到错误一侧的问题。原始记录见 `SceneBaseline.txt`、`PhysicsBaseline.txt` 与 `Docs/PillarCrush/SideValidation.json`。

测试通过真实 `PhysicsScene2D.Simulate` 步进复制的 Stage1 几何，每个物理步记录刚体姿态下的铰链间距、真实碰撞重叠、修复量和穿越事件。连续往返期间不重置玩家位置。

同步的 60/240 Hz 调度测试与实际 PlayerLoop 的 60 FPS 上限/不锁帧测试分别保存报告，不能把模拟调度频率当作实际渲染帧率。固定初始 WorldRoot 原点的额外用例用于覆盖约 21 单位半径的墙；正常关卡的旋转中心跟随玩家，靠墙站立的玩家与那面墙本来就不可能同时相距很远。

初始摆放同时检查真实碰撞和 Tilemap 实心瓦片占地。早期 `Pendulum-additional-quick.json` 将玩家放进轮廓碰撞体包围的实心瓦片，`Pendulum-additional-valid-quick.json` 又包含关卡外侧起点，均保留为测试开发诊断，不作为合法关卡验收结果。

12 个实时用例中 11 个完成全部圈数；全部采样的残留重叠、实际穿透超差和实体原侧穿越均为 0。实时最大铰链间距 0.0000616694 单位，最大当步修复总长 0.150000021（约 2.1e-8 浮点误差）。**实时报告总体 `passed=false`，不能宣称所有压力验收通过。** 帧率配置验证两档均通过。

实际 PlayerLoop 的 60 FPS 档暴露了额外压力配置的限制：将关卡旋转中心强制固定在初始 WorldRoot 原点时，约 101.33° 会形成玩家、右板、Tilemap 三面封闭的局部空间。三面法线的正系数组合为零，向上及反向切线均没有足够通道。保护阻止世界继续压入，实际残留重叠保持 0，但无法达到该用例的 360° 目标。此项不能记作通过；代码不会为完成角度目标而关闭碰撞或把玩家移过墙。不同帧调度影响落点，不锁帧档没有陷入同一夹角并完成了 10 组往返。该固定转轴设置只在压力夹具内使用，没有写回 Stage1 的玩家转轴配置。

测试边界：实时用例克隆同一套 Stage1 实体碰撞几何并调用生产 FixedUpdate；输入由受控目标替代，玩家探针在隔离场景夹具中未布置。因此这里覆盖玩家位置转轴、空中历史位置转轴和固定原点压力配置，不代表已实测 Steam 手柄输入或落地/腾空切换转轴的全流程。自动移动开关、恢复滞回、重力与防推动保持由独立 PlayMode 用例验证。长测结束已恢复临时修改的源场景组件、刚体模拟、帧率与时间倍率，并退出 Play。

## 复测

1. 打开 Stage1 进入 Play，先保持预览：观察两板展开时平行、圆圈与转轴重合；预览中玩家不运行。
2. 开始游戏，持续往两侧旋转世界；观察板顶、板侧与远端墙接触。`CrushGuard.RemainingOverlapCount` 是每步修复后的检测结果。
3. Player 开启旋转暂停开关，旋转时 `AutoMoveVelocityContribution` 应为 0；停止后等 0.15 秒恢复。关掉开关应继续自动横移。重力和防推动在两种状态均保持工作。
   波浪键控制台的“游戏参数”页也可切换此开关，并查看自动移动贡献、残留重叠、预测夹缝阻塞帧和当步抬出位移。
4. Unity Test Runner 的 PlayMode 运行 `GravityGame.Pendulum.PlayModeTests`。其中 Stage1 回归覆盖连续顺逆各 10 圈及额外起点，小型测试覆盖长轴、铰链、位移上限、独立摆动和自动移动暂停。
5. 需要实际帧调度测量时，在已进入 Play 的 Stage1 执行 `Resource.Scripts.Editor.PendulumStageLiveValidation.Begin("rendered", 10)`。运行中用 `Status()` 查看进度；结束后自动恢复临时暂停的源场景组件、帧率和时间倍率，不保存运行时场景改动。
