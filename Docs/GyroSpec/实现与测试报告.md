## 1. 范围与接入方式

按规格第 10 节推进：先完成 JSL 与纯处理类，并取得 T1～T10 全部通过；再接世界旋转；然后实现控制台；最后增加录制、回放与可靠性验证工具。

实现沿用项目目录 `Assets/Resource/Scripts/`、现有 `WorldRotator`、玩家、预览、暂停、死亡和 `SceneTransition`。重力方向、玩家碰撞、氧气死亡和原有场景过渡仍由原系统处理。

2026-09-24 按追加要求移除“旋转时停止”：`PlayerController` 自动移动不再因世界旋转暂停，也不再等待停止后的 0.2 秒；`PivotPendulum` 在旋转期间持续计算重力、阻尼和摆角，移除原冻结与恢复延迟。Stage1 / Stage2 中对应的旧延迟参数已清理。`WorldRotator.IsRotating` 保留供声音和视差使用；预览、菜单暂停、死亡、碰撞及太阳脉冲接口保持原行为。Unity 编译及运行时定向检查通过：旋转时自动移动速度为 `(6, -3)`，转停后立即继续；前进侧墙阻挡、另一侧墙不阻挡、死亡锁定均通过；连续改变世界角度时摆锤摆角从 −180° 更新至 −140.83934°，角速度保持演化，世界重力仍为 `(0, -9.81)`。

- 原生路径：JoyShockLibrary 回调 → 带采样 `deltaTime` 的队列 → 主线程 `GyroProcessor` → `WorldRotationInput` → 现有世界旋转器。
- 模式 A：方向盘角速度映射虚拟摇杆，世界消费每个传感器样本产生的时间积分。
- 模式 B：重力推导方向盘角度，以回正时的世界朝向为基准，按角度倍率和平滑时间追踪目标。
- 输入来源可选陀螺仪、物理右摇杆、两者叠加；陀螺仪缺失时回退右摇杆。键盘 Q/E 保留。
- 控制台提供场景、陀螺仪、游戏参数、性能四页。项目未发现 FMOD 集成，因此按规格 7.7 不创建 FMOD 页；现有声音继续通过 `SfxManager`。
- 控制台使用 IMGUI。按后续用户要求，现已在普通 Build 和 Development Build 中始终包含，无需额外脚本宏；反引号与 Options + Create 的打开方式相同。

### 自动挂载与场景设置

本次陀螺仪和控制台接入**不需要在场景里手动拖拽组件或引用**。`GyroRuntime` 和 `DebugConsole` 在场景加载前自动创建，跨场景保留并防止重复；已有 `WorldRotator` 在 `Awake` 自动补充 `WorldRotationInput`。场景页从 Build Settings 中读取已启用场景。游戏参数页按场景缓存已有玩家、氧气、背包和氧气瓶引用，并提供手动刷新按钮。

运行后按键盘反引号 `~` 对应按键，或手柄 Options + Create 打开控制台。面板默认在屏幕左上角，距左侧和顶部各 10 像素。按住标题栏可以移动，拖动四条边或四个角可以分别拉伸宽高；接近边缘时边框高亮。窗口始终保持在屏幕内，最小 480×320 像素，小屏幕自动适配。顶部“重置窗口”恢复左上角和 70% 大小。

占比显示当前“宽 × 高”，滑条范围为 40%～100%，并提供 50% / 70% / 100% 快捷按钮；这些控件会把宽、高设置为同一屏幕比例，保留当前位置，空间不足时自动移回屏幕内。拖动边缘可以继续自由调整宽高，直到最小尺寸。原有 UI 缩放独立保留；较小面板会限制实际绘制缩放，保证顶部操作仍能显示，陀螺仪页也按面板实际宽度切换单双列。

顶部“保存设置”或陀螺仪页“保存参数”会将窗口位置、大小、占比和其他控制台/陀螺仪设置写入 `Application.persistentDataPath/gyro_settings.json`；窗口以屏幕比例存储，分辨率变化后仍保持可见。旧设置文件缺少窗口字段时仍使用左上角，缺少占比字段时默认使用 70%。游戏参数页的氧气和冲刺数值仅改变当前运行实例，不保存到该 JSON，也不改场景或预制体。

拖动/拉伸追加验证：Unity 编译通过；Play Mode 用实际鼠标拖动标题栏、右下角和左边缘成功，松开后鼠标捕获正常释放。实际 Unity 数学类型运行 24 组边缘/角落拉伸断言，验证最小尺寸、屏幕范围及对边固定；窗口设置 JSON 往返、小屏幕适配、默认重置均通过。截图见 `validation/console-moved-resized.png`。拖动、拉伸和重置不会自动写盘，仍需明确保存。

后续控制台调整已验证：使用 `PlayerBuildInterface.CompilePlayerScripts`，目标 `StandaloneWindows64`、选项 `None`，普通 Player 脚本编译通过；读取生成的程序集确认包含 `DebugConsole` 与四个分页类型。此次未生成或启动完整可执行文件。Play Mode 实际检查了 70% 面板和 40% 面板配合 3x 字号；后者实际适配为 1.878x，并正常切换为单列滚动布局。截图见 `validation/console-70-percent.png`、`validation/console-40-percent.png`。新设置的 JSON 往返、旧 JSON 默认值、上下限和 NaN 回退均通过；控制台关闭后游戏输入恢复。验证没有覆盖用户已保存的参数。Unity Console 没有脚本编译错误；仍有原先 Tile Palette 包的两条有限数值断言，与本次控制台代码无关。

“打开时暂停”会保存并恢复原时间倍率；预览和 HUD 菜单持有的暂停不会被控制台解除。控制台打开时隔离 UGUI、玩家手动移动、跳跃、冲刺、相机缩放和 Q/E 输入。未勾选暂停时，方向盘和世界右摇杆仍可驱动世界，便于观察实时调参；勾选暂停时世界不旋转。

## 5. 第 4 步：录制、回放和内置测试

纯处理、CSV 往返、实际世界回放、三档渲染帧率和真实 300 秒传感器漂移均已验证。下列数据区分模拟输入与实时硬件输入；没有把自动数据模拟当作手持动作验收。

- CSV 保存到 `Application.persistentDataPath/GyroRecordings/时间戳.csv`，记录每次采样的 deltaTime、三轴原始角速度、加速度、重力；回放仍经过 `GyroProcessor.ProcessSample`。
- 录制开始时保存可选 `initialBias` 校准偏移快照，以及 `initialAxis` 方向盘轴与“已穿过退化区”状态。回放与帧率对比恢复这些快照，避免丢失已校准偏移，以及在超过 90° 后开始录制时方向盘符号反转。完整静止均值/方差窗口不序列化，恢复偏移后重新累计窗口；这一点不等价于克隆整个实时处理器状态。
- 回放用真实时间推进，保留记录的采样 deltaTime。暂停时可继续看曲线，但世界遵守预览/暂停/死亡阻断；要观察世界旋转，需开始关卡并解除暂停。
- 回放有效输入来源临时为陀螺仪，物理右摇杆不参与；持久设置中的来源不被覆盖，保存参数不会保存一个临时回放来源。最后一帧先供世界消费积分，再切回 live，切换时清空旧队列和积分。
- 5 分钟漂移测试累计校准后的方向盘角速度，不通过输出死区隐藏漂移；需先完成真机校准，断线或覆盖不足不得显示通过。
- 帧率一致性测试冻结开始时的参数，在实际 60 / 144 / 不锁帧三档下独立回放，不驱动场景。暂时关闭垂直同步，结束或取消后恢复原设置。报告实际 FPS、两种模式角度与误差，未达到目标帧率时不能宣称实际覆盖通过。

## 6. 发现的问题与处理方式

### 传感器时间与渲染时间的冲突

规格要求使用每次传感器回调的 deltaTime，又要求 60 / 144 / 600 FPS 积分一致。如果将 `EndFrame` 的加权平均读数（包括没有新样本时的 20 ms 保持值）直接乘渲染 `Time.deltaTime`，渲染分组会改变传感器脉冲权重，600 FPS 时还会对无新样本帧重复计时。

实现将两者分开：`EndFrame` 保留按采样时间加权的虚拟摇杆读数和最多 20 ms 的显示/输入保持；世界旋转消费 `Σ(mappedOutput × sampleDeltaTime)`，每份积分只消费一次，再乘世界旋转速度与当前游戏时间倍率。暂停和其他阻断期间仍消费并丢弃积分，恢复后不追赶旧输入。

T6 的不采用方案实测为：60 FPS `510.401454153°`、144 FPS `510.777361435°`、600 FPS `510.005096835°`；采用样本时间积分后三档均为 `510.045109294°`。脉冲轨迹的附加测试还专门覆盖了高渲染 FPS 中大量无新样本帧。

### 角度、退化姿势与校准

- 按指定公式 `atan2(-g.x, |X 在水平面上的投影|)` 计算时，分母非负，θ 的测量范围为 **−90°～+90°**。它不提供连续的 360° 方向盘绝对角；超过 90° 后会折回。这是所给公式的限制，控制台已标明。
- 退化区保留最后有效方向盘轴，离开退化区保持轴的同一半球，以防角速度符号突然翻转；附加测试覆盖超过 90° 再返回。
- 默认 B 模式平滑 0.05 s 会造成运动结束瞬间的跟随延迟。因此 T1 同时报告“关闭平滑的几何 90°”及“默认平滑停止后收敛值”，没有把运动终点的 85.68° 隐去。
- 仅检查低方差会把缓慢匀速转动当成静止。校准额外检查低角速度、稳定重力与合理加速度，并用 1.5°/s 慢转用例验证不会错误扣成零。

### 生命周期、暂停和回放

- 原生回调使用持有引用的静态委托，停用/重载前注销回调、停止连接工作线程并清空样本；回调不调用 Unity 场景 API。
- 高 FPS 可能夹着没有传感器样本的帧。`IsRotating` 用不超过 20 ms 的状态保持避免视差/声音误判；它不会给 Transform 增加额外角度。
- 时间倍率在 HUD 暂停期间修改时先挂起，HUD 释放暂停后应用；关闭控制台保留原暂停所有权和原倍率。
- 预览期间世界组件被禁用，因此控制台来源状态直接读取实时服务，不依赖世界上一条命令。
- 模式 B 切换、失去/恢复采样、暂停恢复、回正及脉冲结束都会重建基准，避免旧目标造成跳转。
- 第 4 步审查发现的“录制前已校准、回放却丢失偏移”与“临时回放来源污染持久设置”已纳入修正。偏移快照已有自动回归数值；运行时来源隔离、最后一帧积分和切回实时输入已通过实际场景断言。
- 跨过 90° 退化区后才开始录制时，纯粹重建处理器会丢掉已经保持的轴半球，造成回放反号。CSV 现在同时保存初始方向盘轴和穿越状态，新增自动用例已验证恢复后与 live 同号且数值一致。
- B 模式实际回放初次收到一帧内多个样本时，过去按该帧最后样本回正，可能丢失开头一段运动并随渲染帧率变化。现在按首个录制样本建立基准，并保留到首次世界输入求值；实际 `WorldRotator` 每帧 1 / 2 / 4 样本分组已验证结果一致，证据见 `Step4-PlaybackResults.json`。
